# V5、medium、轮式与机队配置入门

### 任务背景

用户新接手项目，希望理解查询方案中“V5系统设计”“medium轮式混合机队”“旧版全X3配置”的含义。这些词涉及软件、场景、运动与机器人组成几个不同层面，需要分别解释，避免误以为是三套互斥的系统。

### 关键结论

- V5是仓库内一套调度实现的版本称呼，相关代码在 `backend/scheduling_v5/`，不是机器人型号或仓库大小。
- medium是中型仓库布局的名称，当前尺寸为120×90米、48个货架、2304个货位，是“场地”的配置。
- 轮式 `wheeled` 是仿真运动与补能模型选项：按配置推进地面行驶，并支持有限电池库存的换电；medium配置的速度为1.5 m/s，优先换电，不可用时按既有逻辑回退充电。
- 混合机队 `mixed` 表示100台机器人包含不同型号。当前medium配置为A1 15台、R2 15台、X3 70台，各型号的货层可达能力不同。
- 全X3 `all-x3` 表示100台机器人都是X3长臂型，可以操作当前布局的第1～3层，不需要在A1/R2/X3之间按型号筛选，但仍须检查电量、库存和路线等条件。
- “旧版全X3”是对一种历史场景组合的简称；旧地图与全X3并不是必须绑定。地图、运动模型和机队组成可以分别配置，代码中也有旧地图配混合机队的测试。
- 同一套V5调度可以配不同场地和机队，查询模板应读取当前运行配置，而不是为每个数据集复制一套查询代码。

#### 用一个例子区分各层

可以把它理解为一次仓库实验的几项选择：

```text
调度软件：V5，负责协调派单等工作
仓库场地：medium，120×90米、48架、2304货位
运动模型：wheeled，轮式运行与对应补能逻辑
机器人组成：mixed，15台A1 + 15台R2 + 70台X3
任务输入：例如19单或1728单
运行编号：例如exp-001，标记这一次实验
```

任务输入中的“1728单”与旧地图的“1728货位”是两个独立数字，不能因为相同就认为是同一种场景。

#### 当前medium组合与历史常见组合

| 项目 | medium轮式混合机队组合 | 历史常见旧版全X3组合 |
|---|---|---|
| 调度 | V5 | 也可以使用V5 |
| 仓库尺寸 | 120×90米 | 90×76米 |
| 货架/货位 | 48架/2304位 | 36架/1728位 |
| 运动与补能 | wheeled，对应轮式与换电配置 | legacy，历史运动及充电模型 |
| 机队 | A1、R2、X3混合，共100台 | 100台X3 |

这里的legacy是历史模型的程序选项名，不应据此理解为实现了完整的双足行走物理。

#### 与查询设计的关系

例如“这个机器人能不能把货放到第3层”，两种场景都可以复用同一个能力查询流程：

1. 查询当前run中机器人的型号。
2. 查询任务的目标货位层数和要求。
3. 使用项目已有的能力规则判断。

混合机队中A1、R2会被拒绝操作第3层；全X3场景里，每台机器人在型号这一项上都满足要求。变化的是配置和查询结果，不需要逐单重写Cypher。

### 执行过的操作

- 阅读 `README.md` 中的当前与历史布局说明。
- 核对 `config/wheeled-medium-100.json` 中的速度、机队数量和补能策略。
- 阅读 `backend/warehouse/composition.py`，确认运动模型与执行方式的组合。
- 核对 `backend/wide/sim.py` 的默认 `fleet_mode=all-x3`、`backend/domain.py` 的三型号能力定义。
- 用 `./run_in_lade.sh python -B -c '…'` 只读统计两套布局的尺寸、货架和货位数量。
- 没有运行仿真、查询数据库或操作当前服务。
