# 机器人轨迹生成与导航逻辑

### 任务背景

用户继续询问：每台机器人的轨迹如何确定，是否自行导航，以及怎样到达指定货架。本文追踪当前 V5 medium 轮式主线的源码；没有启动仿真或修改运行逻辑。

### 关键结论

- **中央规划路线，机器人按计划执行。** 主进程确定目标点、路径和通行时间，Ray actor 更新每秒位置；actor 没有自行搜索到货架的路线。
- 路径由布局、任务、当前位置及其他机器人的交通预约实时计算，并非预先录制的固定轨迹。
- 当前主线选定 `original-sipp`，即 `SafeIntervalPlanner`：在路网中结合安全时间区间搜索路线，遇到预约冲突可等待或选择其他通路。
- 货位编号会映射为货架外侧的二维服务坐标，机器人移动到该坐标取放货；层高另外用于型号能力检查。
- 中央会规划到取货点、到交货点和返回待命点的路径，加入取放货、等待等停留段，通过电量与预约检查后下发。
- 当前这条执行链是已知地图上的二维运动仿真；位置由轨迹插值计算，没有在这条链里进行真实传感器定位、SLAM 或底盘闭环控制。

#### 1. 先把货位转换成机器人能到达的服务点

布局加载器 `backend/wide/data.py:load_scene()` 根据货架、层数、列号和正反面生成货位，例如 `R21-L1-C8-F1`。

地面目标点的计算为：

```text
x = 货架左边界 + (列索引 + 0.5) × 列间距
y = 货架前边界 - 0.7 m，或货架后边界 + 0.7 m
```

因此导航终点在货架外侧，而不是货架实体内部。同列同面的不同层使用相同地面服务坐标；机器人是否能操作该层，由 `backend/wide/capabilities.py` 检查层数、高度和额外伸展要求。地面导航没有把机器人移到高层货位的三维位置。

#### 2. 从布局生成可行驶路网

`WideNavigator` 读取已知的货架、缓冲区、障碍物、仓库边界和机器人半径。每段路径需通过静态几何碰撞检查。

`WideRoadmap` 继承 `Roadmap` 构建路网：medium 的基础栅格间隔是 0.2 m，路网每 4 个栅格取点，即约 0.8 m 间隔，并连接几何可通行的相邻点。货位服务点、工位和泊位通过精确端点连接接入路网；若起终点之间可直达，也允许直接连接。

V5 复用 V4 的缓存版路网和预约表，以减少重复几何与距离计算；当前选择 `original-sipp` 时，实际路径搜索器仍为 `SafeIntervalPlanner`。

#### 3. 用 SIPP 搜索“路线 + 时间”

普通任务的调用顺序为：

```text
schedule_task()
  → _task_parts()
      → _route()
          → _plan()
              → SafeIntervalPlanner.plan()
```

规划器的搜索状态包括“路网节点”和“该节点的安全时间区间”。它用预计到达时间加剩余路网时间估计来选择搜索顺序，检查目标点是否有足够时间完成取放货，并验证移动期间会不会与其他已预约机器人相撞。

例如 A 已预约某条通道的某段时间，B 的候选路线撞上这个预约，规划器可以推迟 B 的出发时间、插入 `traffic_wait`，或搜索其他可行路径。这不是每台机器人临时观察对方后自行避让，而是在中央规划阶段协调时空占用。

预约表使用连续运动碰撞检查，覆盖机器人沿线段移动的过程；当前模型的机器人半径为 0.55 m，对应中心安全间距约 1.1 m。待命机器人也保留实际占用。

medium 配置限制单段路线搜索的时间范围为 900 秒、搜索扩展预算为 12000。该算法依次考虑已有预约，不保证全部机器人的联合全局最优，也不保证预算内一定能找到所有可能存在的路线。

#### 4. 轨迹下发与逐秒执行

主进程生成的计划包含多个运动或停留段，例如：

```text
当前位置 → 取货点 → 停留取货 → 交货点 → 停留放货 → 待命点
```

每段携带 `a`、`b`、`start`、`end`、`phase`，取放货段还带业务 `marker`。运动段耗时按路程与配置速度计算并向上取整；当前位置按如下公式插值：

```text
比例 = clamp((当前时间 - 段开始时间) / 段持续时间, 0, 1)
位置 = 起点 + 比例 × (终点 - 起点)
```

每个 tick 推进 1 秒仿真时间。两种 Ray 模式的差别为：

| 模式 | actor 的执行职责 | 路线由谁搜索 |
|---|---|---|
| `--ray` | MotionActor 接收当前运动段，返回本秒起终位置 | 主进程 |
| `--robot-processes ray` | RobotActor 持有自身状态和计划，逐秒更新位置、电量、阶段，返回业务标记 | 主进程 |

中央处理取货、卸货与交接标记，更新库存和任务状态。正常执行不会每秒重新搜索整条路线；任务衔接、扰动、故障恢复或持续阻塞等情况可能触发中央重新规划。新任务规划失败时，不提交新计划，保留此前已经提交的安全计划，并进入派单重试流程。
