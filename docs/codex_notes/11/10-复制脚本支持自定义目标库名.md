# 复制脚本支持自定义目标库名

### 任务背景

用户希望确认刚才的 runId 复制脚本如何确定新库名，并在执行复制时指定自己的名称。范围为新容器首次初始化及复制入口的参数传递；没有对现有数据库执行改名、停机、复制或容器创建。

### 关键结论

- 原 shell 入口没有设置初始数据库名，因此 Neo4j 使用默认业务库 `neo4j`；就绪检查也写为 `neo4j`，基础 Python 复制工具的目标默认值同样为 `neo4j`。名称不是根据 runId 或容器名生成的。
- 现已支持 `bash ops/copy_neo4j_run_container.sh <runId> [目标数据库名]`。第二参数可自行填写，省略则保留 `neo4j`。
- 目标名称统一传入 Docker 的 `NEO4J_initial_dbms_default__database`、就绪检查、计划与执行的 `--target-database`，以及最终连接提示。源地址和源库仍为 `bolt://127.0.0.1:47687/neo4j`。
- 当前复用 Neo4j 5.26.32 源镜像。入口接受 3～63 位英文字母、数字、点、短横线，字母开头、字母或数字结尾，不允许下划线、空格、中文或 `system` 前缀；统一转为小写。在调用 Docker、sudo 和读取密码前完成校验。
- 业务库名、Docker 容器名、数据卷名、runId 和用户名是独立概念。自定义库名不会改变容器/卷的时间戳命名规则，用户名仍为 `neo4j`，HTTP/Bolt 端口仍为 48474/48687。
- 参数仅用于全新数据卷首次初始化，不能用来给已有数据卷里的库在线改名。[官方初始库名配置说明](https://neo4j.com/docs/operations-manual/current/configuration/configuration-settings/)
- 10 项离线测试通过，覆盖名称从 shell 入口到各阶段的传递以及原有复制合同；本次没有实际创建容器或导入真实数据。

```bash
bash -n ops/copy_neo4j_run_container.sh
./run_in_lade.sh python -B -m unittest -v tests.test_copy_neo4j_run_container tests.test_copy_neo4j_run
git diff --check
```

- 10 项测试通过，耗时 1.284 秒。shell 语法检查通过；测试仅使用临时目录和替代 Docker/Neo4j 接口，内嵌源预检和目标就绪 Python 代码实际执行，但不连接真实数据库。
- 没有调用真实 Docker、sudo、目标导入或源数据库查询。

### 修改内容

- `ops/copy_neo4j_run_container.sh`：增加可选目标库名、Neo4j 5 兼容的输入校验与小写处理；统一初始化、就绪检查、两次复制和连接提示；保留原来单参数用法。

- 更新原复制准备、通用指南和改名说明，避免旧文档中固定 `neo4j` 的描述与新入口冲突。

### 后续建议

例如要把 `million-110902` 复制到新业务库 `warehouse-copy`，在服务器项目目录执行：

```bash
bash ops/copy_neo4j_run_container.sh million-110902 warehouse-copy
```

将 `warehouse-copy` 替换为自己的名称。脚本按需交互请求 sudo、源数据库密码和新数据库密码；执行前确保该源 run 已停止写入且写入队列排空。此次只修改和验证脚本，没有替用户执行这条创建/导入命令。

连接新业务库时使用对应的名称：

```bash
cypher-shell -a bolt://127.0.0.1:48687 -u neo4j -d warehouse-copy
```

在新实例的 Browser 中可用 `SHOW DATABASES;` 检查名称，并用 `:use warehouse-copy` 选择业务库。真正完成复制以新生成的 `result.json` 的 `status=complete` 为准。该报告位于 `data/neo4j-run-copies/million-110902/<时间>-<进程号>/`。

若之前已创建目标并占用 48474/48687，本脚本仍会创建全新容器和数据卷，不会接管、清空或给旧目标改名；应先确定复用还是迁移，再调整执行方式。当前只增加参数支持，无需再次确认源 runId、地址或源库名。

参考：[Docker 配置映射](https://neo4j.com/docs/operations-manual/current/docker/ref-settings/)、[Neo4j 5 命名规则](https://neo4j.com/docs/cypher-manual/5/cheat-sheet/)、[较新版本数字开头规则的变化](https://neo4j.com/docs/operations-manual/current/database-administration/standard-databases/naming-databases/)。
