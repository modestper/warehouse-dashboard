# 新 runId 输入弹窗修正

### 任务背景

用户反馈点击页面新建运行时只看到 runId 展示，没有直接输入编号的机会。上一版在左侧栏放置可选输入框，但按钮仍弹普通确认框，容易被理解为只显示编号。本次改成点击新建入口直接出现可编辑输入弹窗。

### 关键结论

- “保留记录，另开新run”按钮现在调用输入弹窗，用户可以直接输入新的 runId，确认后才提交。
- 左侧机器人集群标题处的重置按钮也走同一输入流程，两个入口行为一致。
- 弹窗取消不发送创建请求；输入留空仍由后端自动命名；已在侧栏预填的内容会作为弹窗默认值。
- 非法编号不提交，重复编号继续由既有接口拒绝；成功后清空预填框，并提示实际创建的编号。
- 前端11项测试、隔离浏览器7类交互全部通过。只读请求确认当前4173已经返回新页面版本，用户强制刷新即可加载；本轮没有后端修改，无需重启后端。
- 没有对用户当前运行发送控制请求或创建真实run。

### 修改内容

- `dist/original-knowledge.mjs`：将普通确认框改为 `window.prompt()` 输入框，提取共享 `newRun()` 方法并保留校验、成功清空和提示。
- `dist/app.js`：统一控制台的重置入口调用同一个 `newRun()`，不再单独弹只读确认信息。
- `dist/index.html`：说明点击按钮可在弹窗输入，并更新前端资源版本标记。
- 仅新增本文总结。没有修改后端参数、任务调度、当前run或数据库；保留工作区其他修改。
