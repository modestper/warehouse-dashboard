# 仓储操作查询扩充与用途（V2）

当前已有 **14条具体参数化 Cypher（w0～w13）**，均接入同一个只读执行脚本。原来的六条将基础信息合并读取，对任务时序、跨任务货物和执行效果的覆盖不足；这次保留原编号，补充八个独立的决策问题，没有把“高层/低层、低电/高电”等单纯筛选各计一条。

完整运行语句在 [config/warehouse-context-queries.json](../../../config/warehouse-context-queries.json)，入口在 [scripts/warehouse_llm_context_queries.py](../../../scripts/warehouse_llm_context_queries.py)，参数和连接方式见[使用说明](10-仓储操作查询脚本使用.md)。V1 的六条基础设计保留为[历史设计](10-仓储机器人操作查询设计.md)。

## 当前目录

| 编号 | 查询名称 | 帮助判断的问题 |
|---|---|---|
| `w0` | `basis` | 我在什么运行、什么完成步上决策？自己的观测是否可用？ |
| `w1` | `task_pool` | 我空闲时，有哪些已释放的任务值得进一步评估？ |
| `w2` | `task_geometry` | 这个任务到哪里取、到哪里放？我的机械臂能完成剩余操作吗？ |
| `w3` | `task_evidence` | 任务有没有被执行、重新排队或交接？目前有哪些归属和载货证据？ |
| `w4` | `peer_states` | 哪些同伴值得进一步联系或避让？谁可能接走已取下的货？ |
| `w5` | `self_feedback` | 刚才的操作有什么结果？我在等待、耗电还是持续没有进展？ |
| `w6` | `task_timing` | 指定任务从分配到取货、完成分别观察到多长时间？是否有重新排队或多轮执行？ |
| `w7` | `cargo_history` | 这件货跨任务经历了哪些交接？哪些机器人最近的样本仍显示持有它？ |
| `w8` | `progress_summary` | 整个观察窗口内有多少状态样本、空间和电量变化？静止判断的采样依据是否足够？ |
| `w9` | `completion_feedback` | 本机最近实际完成了哪些任务？相对任务期限是提前还是延迟？ |
| `w10` | `recovery_markers` | 最近一次停机、解停或电量校正是什么？是否仍缺少晚于停机的恢复证据？ |
| `w11` | `handoff_outcomes` | 本机最近参与的接力之后，是否观察到任务继续执行或完成？ |
| `w12` | `rack_workload` | 哪些货架被已观察的机器人主任务同时引用？选任务时有哪些作业集中区域？ |
| `w13` | `port_pressure_history` | 已记录的出入库工位件数在最近快照中上升还是下降？是否需要重新评估工位选择？ |

## 新增查询的必要性与具体语句

以下语句直接来自运行目录；`$run_id / $t / $dataset_id / $task_ids / $from_tick` 等由脚本解析并绑定。任务型查询使用实际 Run 关联的数据集；窗口型查询使用 `(from_tick,t]`；其他历史证据均不晚于 t。`result_fetch_limit` 默认17，展示16条并用多取的一条识别截断。

### `w6`：调整等待、重试和接单判断

w3 返回最近有限条执行证据；这里按指定任务的全部已观察事件聚合阶段计数和时间，避免较早的分配事件落在展示上限外。多次分配、取货、完成或出现重新排队时，不将不同执行轮次拼成一次耗时；没有真实运行秒就返回未知，不用 tick 代替秒。

```cypher
MATCH (:Run {id:$run_id})-[:USES_DATASET]->(dataset:Dataset {id:$dataset_id})
UNWIND $task_ids AS requested_task_id
OPTIONAL MATCH (dataset)-[:INCLUDES_TASK]->(task:WarehouseTask {dataset_id:$dataset_id, task_id:requested_task_id})
CALL {
  WITH task
  OPTIONAL MATCH (event:RuntimeEvent {run_id:$run_id, task_id:task.task_id})
  WHERE event.tick <= $t
  RETURN count(event) AS observed_event_count,
    sum(CASE WHEN event.type IN ['task_assigned','dataset_task_assigned'] THEN 1 ELSE 0 END) AS assignment_count,
    min(CASE WHEN event.type IN ['task_assigned','dataset_task_assigned'] THEN event.time END) AS assigned_second,
    sum(CASE WHEN event.type IN ['task_picked_up','picked'] THEN 1 ELSE 0 END) AS pickup_count,
    min(CASE WHEN event.type IN ['task_picked_up','picked'] THEN event.time END) AS picked_second,
    sum(CASE WHEN event.type IN ['task_completed','placed','shipped'] THEN 1 ELSE 0 END) AS completion_count,
    min(CASE WHEN event.type IN ['task_completed','placed','shipped'] THEN event.time END) AS completed_second,
    sum(CASE WHEN event.type = 'task_requeued' THEN 1 ELSE 0 END) AS requeue_count,
    min(event.tick) AS first_observed_tick, max(event.tick) AS last_observed_tick
}
RETURN requested_task_id, task IS NOT NULL AS task_exists, observed_event_count,
       assignment_count, assigned_second, pickup_count, picked_second,
       completion_count, completed_second, requeue_count,
       first_observed_tick, last_observed_tick
```

### `w7`：取货前核对货物身份、交接和持有冲突

w3 按任务查询，这里从指定任务找到 Goods，再跨任务读取同一件货的事件和交接，以及每个机器人不晚于 t 的最新持有样本。可发现货物已出现在后续任务或多个新鲜样本中的情况。INITIAL_AT 明确仅是初始位置；没有持有样本不等于货物在货架。

```cypher
MATCH (:Run {id:$run_id})-[:USES_DATASET]->(dataset:Dataset {id:$dataset_id})
UNWIND $task_ids AS requested_task_id
MATCH (dataset)-[:INCLUDES_TASK]->(:WarehouseTask {dataset_id:$dataset_id, task_id:requested_task_id})-[:CONCERNS]->(goods:Goods)
WITH goods, collect(DISTINCT requested_task_id) AS selected_task_ids
CALL {
  WITH goods
  OPTIONAL MATCH (goods)-[:INITIAL_AT]->(location:Location)
  RETURN collect(location{.location_id, .kind}) AS initial_locations
}
CALL {
  WITH goods
  OPTIONAL MATCH (event:RuntimeEvent {run_id:$run_id, cargo_id:goods.goods_id})
  WHERE event.tick <= $t
  WITH event ORDER BY event.tick DESC, event.id DESC LIMIT $event_fetch_limit
  RETURN collect(properties(event)) AS cargo_events
}
CALL {
  WITH goods
  OPTIONAL MATCH (handoff:Handoff {run_id:$run_id, goods_id:goods.goods_id})
  WHERE handoff.tick <= $t
  WITH handoff ORDER BY handoff.tick DESC, handoff.id DESC LIMIT $evidence_fetch_limit
  RETURN collect(properties(handoff)) AS handoffs
}
CALL {
  WITH goods
  MATCH (robot:Robot {run_id:$run_id})
  CALL {
    WITH robot
    OPTIONAL MATCH (state:AgentState {run_id:$run_id, robot_node_id:robot.id})
    WHERE state.tick <= $t
    WITH state ORDER BY state.tick DESC, state.id DESC LIMIT 1
    RETURN state
  }
  RETURN count(robot) AS known_robots, count(state) AS robots_with_samples,
    collect(CASE WHEN state.cargo_id = goods.goods_id THEN
      state{.robot_id, .tick, .task_id, .cargo_id, .stage,
            age_ticks:$t-state.tick,
            state_fresh:$t-state.tick <= $max_peer_age_ticks} ELSE null END) AS holder_observations
}
RETURN goods.goods_id AS goods_id, selected_task_ids, initial_locations,
       cargo_events, handoffs, holder_observations, known_robots, robots_with_samples
```

### `w8`：决定是否刷新观测、等待或进入恢复判断

w5 返回有限条近期原始样本；这里聚合整个请求窗口的样本数、位置包围范围、电量范围和阶段，并对照已观察完成 Step 数。可识别“首尾相同但期间曾移动”的情况。采样不是每步必有，不能把 Step 数减状态数说成丢帧，更不能由空间范围为0直接判故障。

```cypher
MATCH (:Run {id:$run_id})
MATCH (robot:Robot {id:$run_id+':robot:'+toString($robot_id), run_id:$run_id})
CALL {
  WITH robot
  MATCH (state:AgentState {run_id:$run_id, robot_node_id:robot.id})
  WHERE $from_tick < state.tick AND state.tick <= $t
  RETURN count(state) AS sample_count, count(DISTINCT state.tick) AS sampled_tick_count,
    min(state.tick) AS first_sample_tick, max(state.tick) AS last_sample_tick,
    min(state.x) AS min_x, max(state.x) AS max_x,
    min(state.y) AS min_y, max(state.y) AS max_y,
    count(state.x) AS samples_with_x, count(state.y) AS samples_with_y,
    min(state.battery) AS min_soc, max(state.battery) AS max_soc,
    collect(DISTINCT state.stage) AS observed_stages
}
CALL {
  MATCH (step:Step {run_id:$run_id})
  WHERE $from_tick < step.tick AND step.tick <= $t AND step.complete = true
  RETURN count(DISTINCT step.tick) AS observed_complete_ticks
}
RETURN sample_count, sampled_tick_count, first_sample_tick, last_sample_tick,
       min_x, max_x, min_y, max_y, samples_with_x, samples_with_y,
       min_soc, max_soc, observed_stages, observed_complete_ticks
```

### `w9`：评估最近服务结果与期限表现

w6 针对已选任务分析执行阶段；这里主动发现本机窗口内实际完成的历史任务，关联对应数据集的截止时间，计算真实运行秒下的提前/延迟。多个完成事件或缺少时间时保留歧义，不输出虚假的准时率。

```cypher
MATCH (:Run {id:$run_id})-[:USES_DATASET]->(dataset:Dataset {id:$dataset_id})
MATCH (event:RuntimeEvent {run_id:$run_id, robot_node_id:$run_id+':robot:'+toString($robot_id)})
WHERE $from_tick < event.tick AND event.tick <= $t
  AND event.type IN ['task_completed','placed','shipped'] AND event.task_id IS NOT NULL
WITH dataset, event.task_id AS task_id, min(event.tick) AS completed_tick,
     min(event.time) AS completed_second, count(event) AS completion_event_count
ORDER BY completed_tick DESC, task_id LIMIT $result_fetch_limit
OPTIONAL MATCH (dataset)-[:INCLUDES_TASK]->(task:WarehouseTask {dataset_id:$dataset_id, task_id:task_id})
RETURN task_id, completed_tick, completed_second, completion_event_count,
       task IS NOT NULL AS task_exists, task.task_type AS task_type,
       task.due_time AS due_time, dataset.start AS dataset_start
ORDER BY completed_tick DESC, task_id
```

### `w10`：恢复前检查未解除的停机证据

w5 的短窗口可能看不到很久之前的停机；这里在 t 之前找每类恢复事件的最后记录。停机和解停同 tick 时不擅自确定先后。只报告机器人明确关联的证据，不将“未查到停机”当成当前无故障，也不覆盖未关联机器人的全局故障事件。

```cypher
MATCH (:Run {id:$run_id})
MATCH (event:RuntimeEvent {run_id:$run_id, robot_node_id:$run_id+':robot:'+toString($robot_id)})
WHERE event.tick <= $t AND event.type IN [
  'robot_stopped','robot_stop_cleared','robot_reenabled','robot_power_isolated',
  'battery_measurement_corrected','traffic_retimed','task_requeued']
WITH event.type AS kind, max(event.tick) AS latest_tick
MATCH (latest:RuntimeEvent {run_id:$run_id, robot_node_id:$run_id+':robot:'+toString($robot_id),
                           type:kind, tick:latest_tick})
RETURN properties(latest) AS marker
ORDER BY marker.tick DESC, marker.id DESC LIMIT $result_fetch_limit
```

### `w11`：评估此前求助和接力的结果

w3 只返回指定任务的交接证据；这里发现本机作为交出方或接收方参与过的接力，再关联交接之后的执行样本和首次完成样本。无后续记录是未观察到，不是失败；同 tick 无法判定先后的完成不算已证明的交接后完成。延迟单位为 tick。

```cypher
MATCH (:Run {id:$run_id})
MATCH (handoff:Handoff {run_id:$run_id})
WHERE $from_tick < handoff.tick AND handoff.tick <= $t
  AND (handoff.donor_id = $robot_id OR handoff.receiver_id = $robot_id)
WITH handoff ORDER BY handoff.tick DESC, handoff.id DESC LIMIT $result_fetch_limit
CALL {
  WITH handoff
  OPTIONAL MATCH (state:ExecutionState {run_id:$run_id, task_id:handoff.task_id})
  WHERE handoff.tick < state.tick AND state.tick <= $t
  WITH state ORDER BY state.tick DESC, state.id DESC LIMIT 1
  RETURN properties(state) AS post_transfer_sample
}
CALL {
  WITH handoff
  OPTIONAL MATCH (done:ExecutionState {run_id:$run_id, task_id:handoff.task_id, status:'completed'})
  WHERE handoff.tick < done.tick AND done.tick <= $t
  WITH done ORDER BY done.tick, done.id LIMIT 1
  RETURN done.tick AS completion_tick
}
RETURN properties(handoff) AS handoff,
  CASE WHEN handoff.donor_id = $robot_id THEN 'donor' ELSE 'receiver' END AS my_role,
  post_transfer_sample, completion_tick,
  CASE WHEN completion_tick IS NOT NULL THEN completion_tick-handoff.tick ELSE null END AS observed_completion_latency_ticks
ORDER BY handoff.tick DESC, handoff.id DESC
```

### `w12`：接单时避开已观察到的作业集中货架

w4 只描述同伴状态；这里把机队最新状态里的主任务关联到对应数据集的货位，按货架聚合任务引用、机器人和新鲜引用数。无需逐个再读取同伴任务定义。它不是机器人实际占位、完整批任务需求或道路预约，也不将出库源货层直接当作尚未完成的机械臂要求。

```cypher
MATCH (:Run {id:$run_id})-[:USES_DATASET]->(dataset:Dataset {id:$dataset_id})
MATCH (robot:Robot {run_id:$run_id})
CALL {
  WITH robot
  OPTIONAL MATCH (state:AgentState {run_id:$run_id, robot_node_id:robot.id})
  WHERE state.tick <= $t
  WITH state ORDER BY state.tick DESC, state.id DESC LIMIT 1
  RETURN state
}
WITH dataset, robot, state WHERE state.task_id IS NOT NULL
MATCH (dataset)-[:INCLUDES_TASK]->(task:WarehouseTask {dataset_id:$dataset_id, task_id:state.task_id})
      -[:FROM|TO]->(location:Location)
WHERE location.kind = 'slot'
RETURN location.rack_id AS rack_id,
  collect(DISTINCT robot.robot_id) AS observed_robot_ids,
  collect(DISTINCT task.task_id) AS observed_task_ids,
  collect(DISTINCT location.level) AS referenced_slot_levels,
  count(DISTINCT robot.robot_id) AS observed_robot_count,
  count(DISTINCT CASE WHEN $t-state.tick <= $max_peer_age_ticks THEN robot.robot_id ELSE null END) AS fresh_reference_count,
  min(state.tick) AS oldest_state_tick, max(state.tick) AS newest_state_tick
ORDER BY fresh_reference_count DESC, observed_robot_count DESC, rack_id
LIMIT $result_fetch_limit
```

### `w13`：需要选择或重新评估物理工位时查看压力变化

w1 只提供一个快照；这里读取窗口内多份轻量工位计数摘要，比较实际出现的同一工位件数变化，避免读取每份快照的大型待办队列。只描述返回快照中的变化；某快照缺少一个工位键时不补0，件数下降也不代表工位已经预约给本机。

```cypher
MATCH (:Run {id:$run_id})-[:USES_DATASET]->(:Dataset {id:$dataset_id})
MATCH (snapshot:DispatchState {run_id:$run_id, dataset_id:$dataset_id})
WHERE $from_tick < snapshot.tick AND snapshot.tick <= $t
RETURN snapshot.tick AS observed_tick, snapshot.commit_seq AS commit_seq,
       snapshot.elapsed AS elapsed, snapshot.ports_json AS ports_json
ORDER BY observed_tick DESC, commit_seq DESC LIMIT $result_fetch_limit
```

## 执行与兼容

```bash
# 输出全部14条具体语句和自动参数规则，不连接数据库。
./run_in_lade.sh python scripts/warehouse_llm_context_queries.py   --run-id test_110404 --queries all --dry-run

# 运行新增八条；完成步、数据集和任务候选按依赖自动读取。
./run_in_lade.sh python scripts/warehouse_llm_context_queries.py   --run-id test_110404 --robot-id 1 --queries w6-w13 --print-context

# 只评估近期完成和接力效果；此包不需要当前存在候选任务。
./run_in_lade.sh python scripts/warehouse_llm_context_queries.py   --run-id test_110404 --robot-id 1 --queries memory_review
```

runId 要替换为当前实际运行。原 `w0～w5` 保持兼容，默认 `core` 仍为 `w0,w5`；`all` 现在包含14条，不建议每次操作无差别全查。新增 `task_progress / memory_review / local_awareness / data_readiness` 包，并扩充接单、执行、求助、能源和恢复包。`--list-queries` 显示实际组成。执行器现与 LaDe 一样逐条自动提交：单条执行/提交失败后继续尝试后续查询，仍保留时间锚点和任务输入保护。

`w2/w3/w6/w7` 需要任务输入：有显式任务就使用显式任务；否则先用本机任务，必要时读取候选池。无已观察任务时明确跳过，不能改成扫描整天静态任务。其他新增查询不依赖当前候选任务。所有读取仍固定 Run 和时间锚点，不认领任务或修改运行状态。

新任务查询显式使用 `(dataset_id,task_id)`，与静态导入声明的复合索引一致。货物维度查询 `w7` 还需要在实库用 EXPLAIN 检查访问计划；当前源码没有声明 `RuntimeEvent(run_id,cargo_id,tick)` 和 `Handoff(run_id,goods_id,tick)` 索引，大数据下可能扫描较多记录。这次没有执行建索引或数据库写入。

## 验证与未解决项

- 30项本地测试通过；覆盖逐条自动提交、单条失败后继续、每条超时和依赖保护，以及重派任务阶段耗时歧义、持有样本冲突、窗口空间范围、期限反馈、恢复歧义、工位缺键和并发日志等。
- `--list-queries` 和全目录 `--dry-run` 已验证，14条查询的全部参数都能由脚本解析。八条新增语句来自当前图谱已有标签、关系和属性，没有引入假想库存/道路/电池节点。
- 9项 Neo4j 隔离测试已提供，包含14条语句的 EXPLAIN/实际执行、跨 Run/数据集与未来事件隔离、业务样例，以及服务端语法错误后的自动提交恢复。本环境未配置测试 URI 和连接密码，9项均跳过；**不能把本地测试当作实库编译、业务执行或性能通过**。
- 实时库存、完整故障、道路和资源预约、换电电池余量、有效协助承诺依旧缺少完整图谱事实；这些缺项未因查询数量增加而解决。原静态导入中的货架引用问题、历史配置及写入 epoch 校验也未在本次修改。
