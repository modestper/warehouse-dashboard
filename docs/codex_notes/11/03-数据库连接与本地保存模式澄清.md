### 任务背景

用户希望确认：安装本机 Neo4j、开放 47687 端口后，仓储仿真是否会自动从本地保存切换为数据库写入，以及应该如何配置项目连接。

### 关键结论

- 不存在“47687 不通就保存本地、47687 通了就自动写图谱”的切换逻辑。之前的仿真命令显式使用 journal，图谱 writer 开关也没有打开。
- 当前核对到的本地运行 manifest 仍为 knowledge_backend=journal、robot_graph=false、global_writer=false、robot_processes=off、ray=false、legacy_a_graph=false。
- 端口监听只代表一个服务可能可以访问，不代表密码、数据库名正确，更不代表项目已经向其写入。
- 查询、静态导入、机器人运行态写入、全局事实写入是不同功能，配置 URI 与密码只解决连接参数，不自动启用全部功能。
- 当前新图谱路径依赖 robot-processes ray、robot-graph 和 global-writer-url；本地 journal 可同时保留。
- 连接环境应在启动相关进程之前设置，已经运行的 Python 服务不会自动获得另一个终端刚设置的环境变量。
- 数据库名必须和实际 SHOW DATABASES 结果一致；此前创建命令缺少首次命名参数，不能默认 warehouse 一定已创建。

### 执行过的操作

- 读取 `ops/warehouse_live_runtime.py` 中存储创建、旧 mirror 开关和全局 writer 配置。

- 使用 `./run_in_lade.sh python -c ...` 读取当前本地 live-manifest，未读取密码或连接数据库。

### 修改内容

仅新增本文，没有修改应用配置、环境、服务或数据库。

#### 1. 实际模式判断

```text
旧命令显式选择 journal，未启用图谱 writer
  → 保存本地 journal.sqlite、checkpoint 等
  → 是否存在 47687 不改变这项选择

配置环境变量并启用相应图谱功能
  → 使用指定 URI/用户/密码/数据库连接
  → 初始化/查询/运行态 writer 才会实际访问图谱
```

本地持久化和图谱写入可以并存。较新 C 套运行态写入与 knowledge-backend=journal 并不冲突；也不应仅将 knowledge-backend 改为 neo4j 就认为所有 actor 和全局事实已经接入。旧 A 套镜像还需要显式 legacy-a-graph，本次不建议为新路径启用它。

查询对象在 live 启动时读取连接参数，但延迟创建驱动；在查询或健康检查时访问数据库。写入失败的具体处理随路径而异，不能概括成统一静默退回本地。

#### 2. 在启动进程的终端配置连接

```bash
export WAREHOUSE_NEO4J_URI='bolt://127.0.0.1:47687'
export WAREHOUSE_NEO4J_USER='neo4j'
export WAREHOUSE_NEO4J_DATABASE='warehouse'
read -rsp '输入 Neo4j 密码：' WAREHOUSE_NEO4J_PASSWORD
echo
export WAREHOUSE_NEO4J_PASSWORD
```

如果 SHOW DATABASES 返回的业务库名是 neo4j，则 DATABASE 应填 neo4j；仅修改变量不会重命名数据库。

各进程继承其启动终端的环境。独立全局服务和仿真在不同终端启动时，两个终端都需要设置连接参数。进程已启动后，修改 shell 变量不影响该进程，需在配置正确的环境下重新启动相应服务。

#### 3. 各功能需要什么

| 目标 | 必需配置或操作 |
|---|---|
| 让 kg 页面查询本机图谱 | 在 live 启动前设置连接变量；请求时进行实际查询 |
| 导入静态地图、货物与任务 | 配置变量后运行 scripts/import_warehouse_neo4j.py --apply |
| 写每步机器人状态与事件 | 使用 --robot-processes ray --robot-graph，并准备 Ray 运行环境 |
| 写完整全局 Step 与统计 | 启动 backend.global_writer_api，再向 live 传 --global-writer-url |
| 从图谱读取当前状态派单 | 另设 --kg-state-source neo4j；默认 memory 不影响是否写图谱 |

在 Ray head 已就绪、静态数据已准备好、两个终端都已设置连接环境的前提下，示例为：

终端一：

```bash
./run_in_lade.sh python -m backend.global_writer_api --port 14284
```

终端二（选独立 14583 端口，新建快速样例运行）：

```bash
./run_in_lade.sh python -m backend.warehouse live \
  --registry config/live-wheeled-datasets.json \
  --dataset-id medium19 --output-root data/local-runs \
  --mode rules --knowledge-backend journal --mobility wheeled \
  --robot-processes ray --ray-address 127.0.0.1:26380 \
  --robot-graph --global-writer-url http://127.0.0.1:14284 \
  --kg-state-source memory --port 14583
```

该示例没有 --autostart；页面开始后才推进。它需要已有 Ray head，不能当成无需前置服务的一条命令。14284 是全局 HTTP 服务端口，47687 才是 Neo4j Bolt 端口。

### 后续建议

- 先确认实际数据库名和凭证，再决定只连接图谱页面，还是完整启用仿真运行态写入。
- 验证应以真实查询返回、writer 状态与本次 runId 的运行态节点为准，不能只检查端口监听。
- 本次没有实际连接数据库，不能宣称新安装的 Neo4j 已经被仿真使用。
