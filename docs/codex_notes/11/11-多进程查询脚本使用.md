# 多进程操作上下文查询

新增入口：[scripts/warehouse_llm_context_queries_multiprocess.py](../../../scripts/warehouse_llm_context_queries_multiprocess.py)。原线程版脚本、查询读取模块、14条 Cypher 目录和旧测试/说明保持不变。新入口复用当前版本的查询选择、参数保护、逐条自动提交及结果处理，使用独立进程池执行。

## 运行100进程并发查询

在仓库根目录执行，将 `test_110404` 换成实际运行的 runId：

```bash
./run_in_lade.sh python scripts/warehouse_llm_context_queries_multiprocess.py \
  --run-id test_110404 --robot-ids 1-100 \
  --queries all --max-workers 100 --repeat 5
```

这会计划500个 context（100台机器人×5次），查询子进程数上限为100。每个 context 内所选语句依次执行，任务缺失或观测条件不满足时按当前读取逻辑跳过。并发的单位是 context，不会在每个子进程内再启动100个线程。

`--max-workers` 省略时默认等于所选机器人数量；只选择一台机器人时默认为1。最大进程容量还受 context 总数限制，例如只有一份 context 时最多使用一个查询进程。实际返回过 context 的 PID 记录在结果中，不能仅凭配置值认定已经有100条 SQL 同时在服务端执行。

`repeat` 与原查询脚本的计数含义一致：每台机器人生成N次 context，按任务队列分发；不同轮次可以重叠，不保证整轮同步，也不将机器人永久绑定到固定 PID。

## 连接与事务

- 使用 `spawn` 启动子进程；主进程只传递连接配置、查询参数和任务编号，不创建或跨进程传递 Neo4j Driver、Session 或 Transaction。
- 每个子进程首次处理任务时独立创建并校验 Driver，后续 context 复用该进程内的 Driver；正常退出时通过进程清理回调关闭连接。
- 每个 context 新建只读 Session，每条 `session.run()` 使用自己的自动提交事务。完整读取并消费结果后再执行下一条；单条失败会记录错误并继续尝试后续满足依赖的查询。
- `--max-connection-pool-size` 是**每个子进程**的连接池上限，默认1。`--transaction-timeout` 默认30秒，作用于每条查询事务。

连接参数沿用 `--uri / --user / --database / --password` 和 `NEO4J_* / WAREHOUSE_NEO4J_*` 环境变量，优先级与原版一致。交互终端缺密码时，仅由主进程提示输入一次；子进程使用主进程传入的配置，不会各自询问。输出文件不保存密码。

## 离线查看、固定时间和选择查询

```bash
# 不启动子进程、不连接数据库：查看100进程、500个context的计划。
./run_in_lade.sh python scripts/warehouse_llm_context_queries_multiprocess.py \
  --run-id test_110404 --robot-ids 1-100 \
  --max-workers 100 --repeat 5 --queries all --dry-run

# 查看原有14条语句及查询包。
./run_in_lade.sh python scripts/warehouse_llm_context_queries_multiprocess.py --list-queries

# 固定已完成步100；10个子进程并发，每台机器人重复3次。
./run_in_lade.sh python scripts/warehouse_llm_context_queries_multiprocess.py \
  --run-id test_110404 --robot-ids 1-100 --tick 100 \
  --queries task_decision --max-workers 10 --repeat 3 \
  --output-dir /tmp/warehouse-context-processes-001
```

`--tick` 省略时，每份 context 分别读取一次最新完成步；要比较同一逻辑步，须显式传入一个已发布的 tick。同一 context 的所有语句复用取得的 Run、tick 和数据集身份，逐条自动提交本身不提供跨查询历史快照。

其余参数保持熟悉的用法：`--task-id / --task-ids / --max-tasks / --history-ticks / --param / --include-cypher / --print-context / --explain`。新文件的 `--help` 提供完整说明。

## 输出与核对进程

默认输出到 `data/warehouse_context_queries_multiprocess/时间戳-随机后缀/`；可通过 `--output-dir` 指定尚不存在的新目录。所有结果均由主进程汇总写入，不让多个子进程争写同一文件。

| 文件 | 内容 |
|---|---|
| `contexts.jsonl` | 每份 context 的事实、缺项、实际 `worker_pid`、`parent_pid`、`repeat_index`、连接初始化标记和耗时 |
| `queries.jsonl` | 每条查询的参数、状态、行数、耗时、`worker_pid`、`repeat_index`，可选完整 Cypher |
| `summary.json` | 原有查询/上下文统计，以及 `worker_pids / process_count / processes` 和每进程连接初始化次数 |

`process_count` 是实际返回过 context 的子进程 PID 数，不是单看配置得到的数字。进程可能处理不同机器人的 context；用 `context_index` 唯一关联一份 context，用 `robot_id + repeat_index` 识别重复次数，`repeat_index` 从0开始。

`driver_setup_ms` 记录该 context 首次初始化连接的开销，复用时为0；`worker_elapsed_ms` 包含连接准备和读取；`queue_ms` 是提交到子进程开始执行之间的时间，包含等待和进程启动影响。整批 `wall_ms` 包括进程启动、任务、文件写入和正常回收。进程异常退出、任务提交失败或结果无法返回时记录失败 context，未知 PID 保留为 null，不伪造已测耗时；这类未测 context 不进入上下文耗时分位数。

退出码沿用：0为批次正常完成（可能有显式观测缺项），1为连接/查询/进程错误或存在 unavailable context，2为参数或凭据缺失。
