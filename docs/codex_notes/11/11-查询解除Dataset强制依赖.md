# 查询解除 Dataset 强制依赖

## 结论与改动

查询目录升级为 `warehouse-operation-context-v3`，保留 `w0`～`w13` 共14条具体语句。线程、多进程和 Ray 三个入口共用修改后的读取模块；并发方式、repeat、逐条只读自动提交保持原有行为。

- `w0` 的公共门槛只要求有效的 Run 和已发布完成 Step，不再要求 Dataset 节点或 `USES_DATASET` 关联。Dataset 元信息仍可选返回；缺失不导致 `anchor_unavailable`。元信息冲突只影响静态命名空间回退。
- `w1/w13` 按 runId 读取调度快照；`w3/w6` 按 runId、task_id、历史时间直接读执行和事件，任务定义缺失也能返回结果。`w3/w6` 使用 `task_observed` 表示运行证据是否存在，不把静态定义存在与否混为一谈。
- `w2/w7/w9/w12` 优先通过当前 run 的 Execution 关联定位静态任务；无关联时，仅按运行中明确、无冲突的数据集标识匹配任务属性。这一步不需要 Dataset 节点存在，也不会仅凭 task_id 在全库寻找同名任务。歧义返回未知，不任意选择。
- `w7` 还可从已观察的 ExecutionState、RuntimeEvent、Handoff 获得货物身份，随后按当前 run 查货物历史；不再强制需要 Goods 定义。多个冲突货物标识明确报告未知。
- 完成事件与任务引用先独立读取：`w9` 缺期限背景时保留完成事件，延迟为 null；`w12` 缺货架定义时保留任务引用，rack_id 为 null。缺位置、布局、时间原点时不编造机械臂能力或截止时间。
- `w0/w4/w7/w12` 获取最新机器人采样时，先利用写者已有的确定性状态 ID 查指定 tick；无该采样才回退到不晚于 tick 的最近历史。保留稀疏采样和旧 ID 的兼容性，不创建或修改数据库索引。

Dataset 的业务标识仍可作为静态任务的可选命名空间；它不是 `--database neo4j`。用户无需新增 Dataset 参数，原有启动命令继续可用。

## 输出解释

缺 Dataset 不再导致其余13条查询统一跳过。若没有本机任务、显式任务或候选任务，依赖任务 ID 的语句仍会合理跳过并记录 `no_observed_task_ids`；空历史窗口同样有独立跳过原因。因此个别语句仍可能没有延迟样本，不能把“14条存在”理解成每次都必须执行14条。

此修复不会补齐数据库里缺失的货架、任务定义和时间原点，也不能消除实际事务超时。旧日志不会重算；再次执行原命令会生成新日志。
