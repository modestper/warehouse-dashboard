# 任务生成脚本与使用方法

### 任务背景

用户希望找到当前仓储任务生成代码，了解如何设置参数、生成任务包并让仿真使用它。本次只读检查源码及 CLI 帮助，没有生成任务、导入 Neo4j、切换或重启运行。

### 关键结论

- 当前统一入口是 `./run_in_lade.sh python -m backend.warehouse generate`，路由代码在 `backend/warehouse/__main__.py`。单场景实现为 `backend/wide/scenarios.py`，连续多日实现为 `backend/wide/multiday.py`。
- 单场景支持 uniform、peak、hotspot、continuous，按活动货位、周转间隔和持续时间决定任务量；多日生成器支持明确设置 days、profiles、tasks_per_day、date，并跨日延续库存和货物身份。
- `--active-slots` 是参与产生任务的货位数，不是活跃机器人数。机器人数量、行驶速度、电量、故障、写图模式及运行倍速属于仿真配置，不由任务 CSV 分配。
- 当前统一 CLI 的 `--tasks-per-day`、`--days`、`--profiles`、`--date` 只在 multiday 分支传入生成函数；单场景不能靠这些参数控制任务总量或日期。尤其 `--date` 虽显示在统一帮助中，单场景分支没有转发，仍使用函数默认日期 2026-10-27。本次未修复这个参数接线问题。
- 标准任务包至少包含 tasks.csv、initial_inventory.csv、manifest.json，生成器还保存 validation.json。多日包另有 profiles-report.json、reference-inventory.json 等辅助报告。校验通过只说明数据和参考依赖有效，不承诺任意负载下机器人都能按期完成。
- 新任务包不会自动出现在实时页面。批处理可用 `--dataset` 直接指定；现有 Neo4j 实时启动器通过 `--registry` 和 `--dataset-id` 选择，需要注册与任务包匹配的地图、位置表和独立 graph_dataset_id。
- `scripts/generate_warehouse100_dataset.py` 是另一套固定均衡周转单日生成器；`generate_warehouse_dataset.py` 是早期图谱实验 CSV 生成器；`generate_million_runtime_dataset.py` 生成运行态回放样本。它们不应混同于当前标准场景生成入口。

### 后续建议

#### 1. 复用单场景生成器

从项目根目录执行。以下示例使用原 36 架、1728 货位地图，生成 24 小时均匀输入；目录必须尚不存在：

```bash
./run_in_lade.sh python -m backend.warehouse generate \
  --kind uniform \
  --scene data/layouts/warehouse100-wide-v2.json \
  --duration-seconds 86400 \
  --active-slots 1728 \
  --slot-interval-seconds 21600 \
  --seed 20261109 \
  --output data/datasets/my-day-20261109
```

此组合每个活动货位在 24 小时内释放 4 个交替 IN/OUT 任务，共 1728×4=6912 条。不同种子会改变初始库存与相位等分布。目录名中的日期只是目录名；当前单场景默认任务日期仍是 2026-10-27。

若要一小时集中高峰，可在新目录使用：

```bash
./run_in_lade.sh python -m backend.warehouse generate \
  --kind peak \
  --scene data/layouts/warehouse100-wide-v2.json \
  --duration-seconds 3600 \
  --active-slots 1728 \
  --slot-interval-seconds 3600 \
  --seed 20261109 \
  --output data/datasets/my-peak-20261109
```

此组合生成 1728 条任务，peak 会压缩到三个波次，并非每秒均匀释放。生成新高峰不保证当前仿真必然达到百台同时作业，需要运行结果验证。

| 参数 | 含义 |
|---|---|
| --kind uniform | 均匀周转，随机初始相位 |
| --kind peak | 三个集中释放波次 |
| --kind hotspot | 最近的一片活动货位提高周转频率，任务总量会变化 |
| --kind continuous | 每货位独立指数到达间隔，任务数随随机结果变化 |
| --duration-seconds | 任务释放窗口，单位仿真秒 |
| --active-slots | 参与任务生成的货位数量，不改变地图容量或机器人数量 |
| --slot-interval-seconds | 每货位名义周转间隔，最小 60 秒；通常越小任务越密 |
| --seed | 随机种子；固定源码、地图、参数与 seed 才能讨论重现 |
| --max-tasks | 生成任务条数预算，默认 250000，不是要求精确生成这么多条 |
| --scene | 地图，必须与后续仿真及位置表一致 |
| --output | 全新的任务包目录；已存在会拒绝 |

#### 2. 指定任务总数和起始日期

用 multiday，即使只生成一天也可以：

```bash
./run_in_lade.sh python -m backend.warehouse generate \
  --kind multiday \
  --scene data/layouts/warehouse100-wide-v2.json \
  --days 1 \
  --profiles uniform \
  --tasks-per-day 6912 \
  --date 2026-11-09 \
  --seed 20261109 \
  --output data/datasets/my-dated-day-20261109
```

这里 --date 确实会传入多日生成函数。把 --days 改为 7 可生成连续七天；--profiles 可逗号分隔指定循环，例如：

```text
uniform,fixed_peak,local_hotspot,batch_pulses,moving_hotspot,tidal,mixed_recovery
```

mixed_recovery 默认使用 1.25 倍日量，默认七种日型、基准 6912 条/日时共 50112 条。uniform/fixed_peak 等其余日型按基准日量。需要修改批次大小、最低货位间隔、期限裕量和混合日倍数时，用直接模块入口：

```bash
./run_in_lade.sh python -m backend.wide.multiday --help
```

直接模块额外提供 --batch-size、--minimum-slot-gap-seconds、--deadline-slack-seconds、--mixed-load-factor。修改任务量过高可能因容量/参考依赖或预算而拒绝生成，不能靠提高 max-tasks 保证负载物理可行。

#### 3. 独立校验并使用

以第一个示例为例：

```bash
./run_in_lade.sh python -m backend.warehouse validate \
  --scene data/layouts/warehouse100-wide-v2.json \
  --dataset data/datasets/my-day-20261109
```

若只想离线运行，可直接指定目录，下面是明确规则模式和本地 journal 的短跑示例，不是当前 Neo4j 无 journal 实时模式：

```bash
./run_in_lade.sh python -m backend.warehouse run \
  --scene data/layouts/warehouse100-wide-v2.json \
  --dataset data/datasets/my-day-20261109 \
  --mobility legacy --mode rules --knowledge-backend journal \
  --output data/local-runs/my-day-run-20261109 \
  --run-id my-day-run-20261109 --until 300
```

如果需要原有 Neo4j 实时启动器，建议创建单独注册表（不要覆盖已有注册项）。例如新建 config/my-generated-datasets.json：

```json
{
  "version": "warehouse-live-datasets-v1",
  "base_directory": "..",
  "default_dataset": "my-day",
  "datasets": {
    "my-day": {
      "label": "自定义全天输入",
      "scene": "data/layouts/warehouse100-wide-v2.json",
      "dataset": "data/datasets/my-day-20261109",
      "mobility": "legacy",
      "locations_csv": "docs/dataset-contract/layout/task-locations.csv",
      "graph_dataset_id": "dataset:warehouse-custom:my-day-20261109"
    }
  }
}
```

此文件是说明示例，本次没有实际创建。先用只读列举核对注册结果：

```bash
./run_in_lade.sh python ops/start_neo4j_live.py \
  --registry config/my-generated-datasets.json --list-datasets
```

之后在保留已有 Neo4j 连接环境的前提下，显式选择新输入、新 runId 和空闲端口启动：

```bash
./run_in_lade.sh python ops/start_neo4j_live.py \
  --registry config/my-generated-datasets.json \
  --dataset-id my-day \
  --run-id my-day-live-20261109 \
  --port 14583
```

这条启动命令会执行静态导入并启动新仿真，实际运行前应确认端口空闲，数据库地址/库名正确。若改用 medium 地图，生成、校验、注册三处 scene 都应切换为对应地图，locations_csv 改为 medium 配套表，同时采用 mobility=wheeled 和 config/wheeled-medium-100.json。不能只改数据目录仍沿用旧地图。

#### 4. scripts 下其他生成器的用途

| 文件 | 用途及区别 |
|---|---|
| scripts/generate_warehouse100_dataset.py | 固定一天均衡轮转任务包，按 layout/locations 和 cycles 控制；旧地图默认 cycles=4 时为 6912 条。与 scenarios.py 的逐货位交替方式不同。 |
| scripts/generate_warehouse_dataset.py | 早期图谱实验 CSV，可用 --count、--robot-count、--day、--dry-run；字段和包结构不能直接当成标准 V5 输入。 |
| scripts/generate_current_layout_graph_dataset.py | 为旧 32×22 演示布局生成图谱包，脚本直接执行会写固定目录且使用覆盖选项，不是当前统一入口。 |
| scripts/generate_million_runtime_dataset.py | 生成机器人运行态 JSONL 回放样本，不是业务任务到达生成器。 |

当前任务无需用户确认；若下一步要实际生成并启动实验，应使用新输入目录、新 runId，保留已有记录。
