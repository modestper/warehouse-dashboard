# 任务集与启动参数对应表

> 更新：本文下方记录注册前的入口情况。后续已完成全部9套注册，当前启动器均支持 `--dataset-id`；最新对应关系及命令见 [数据集注册与启动](../../REGISTERED_DATASETS.md)。`s4173` 的现有两个参数形式保持不变。

### 任务背景

在已完成九套任务集数量和分布统计的基础上，整理每套任务集对应的选择参数、注册表、地图和配置，明确当前 `s4173` / Neo4j 启动器能直接运行哪些输入。本次只读取配置、核对 CLI 并新增文档，不启动仿真，不写数据库，不修改启动函数。

### 关键结论

- 当前 `ops/start_neo4j_live.py` 只接受 `--dataset-id medium19` 和 `--dataset-id medium1728`，使用 `config/live-wheeled-datasets.json`。
- `/home/chioe/.bashrc` 中的 `s4173` 固定传入 `--dataset-id medium19`；它只接受运行编号和写图方式两个位置参数，尚未提供任务集参数。
- 旧实时注册表 `config/live-datasets.json` 的 `sample19`、`peak1728` 对应旧地图；这些名字不是当前 Neo4j 启动器的合法选项。
- 旧注册表里的 `seven-patterns` 指向不存在的 `data/datasets/live-seven-patterns`，并未指向仓库实际包含的七日参考包；当前不可直接使用这个别名。
- `day`、`peak-2h`、`hotspot-2h`、`continuous-2d` 尚未注册实时别名；历史批处理通过 `--dataset` 指定目录，同时配套原地图和配置。当前无 journal 的轮式启动方式尚未覆盖这些输入。
- 任务量和到货时间来自固定 CSV；`KG_WRITE_MODE`、运行编号和仿真倍速均不选择或重新生成任务。生成器参数与运行参数分开使用。

#### 一、九套任务集与选择参数

下表数据路径均相对于项目根目录；`--dataset-id` 与 `--dataset` 属于不同入口，不能混用。

| 任务集目录（均在 `data/examples/` 下） | 任务数 / 业务时长 | 选择参数 | 入口与当前可用情况 |
|---|---|---|---|
| `wheeled-medium-sample19` | 19 / 30分钟 | `--dataset-id medium19` | 当前 Neo4j 启动器直接支持；当前 `s4173` 固定使用 |
| `wheeled-medium-peak` | 1728 / 1小时 | `--dataset-id medium1728` | 当前 Neo4j 启动器直接支持 |
| `warehouse-v5` | 19 / 30分钟 | `--registry config/live-datasets.json --dataset-id sample19` | 旧实时入口 `ops/warehouse_live.py` 支持；不是当前启动器选项 |
| `regression/peak` | 1728 / 1小时 | `--registry config/live-datasets.json --dataset-id peak1728` | 旧实时入口支持；也可使用历史批处理 `--dataset` |
| `regression/day` | 6912 / 24小时 | `--dataset data/examples/regression/day` | 历史批处理；无现成实时别名 |
| `regression/peak-2h` | 768 / 2小时 | `--dataset data/examples/regression/peak-2h` | 历史批处理；无现成实时别名 |
| `regression/hotspot-2h` | 924 / 2小时 | `--dataset data/examples/regression/hotspot-2h` | 历史批处理；无现成实时别名 |
| `regression/continuous-2d` | 1034 / 48小时 | `--dataset data/examples/regression/continuous-2d` | 历史批处理；无现成实时别名 |
| `seven-patterns-20261028` | 50112 / 7天 | `--dataset data/examples/seven-patterns-20261028` | 历史批处理可显式指定；旧实时别名 `seven-patterns` 的目标路径当前不存在 |

当前启动器没有 `--dataset`、`--registry` 或 `--config-json` 参数，不能把上述旧数据参数直接追加到 `ops/start_neo4j_live.py`。

#### 二、当前两个 medium 选项自动绑定哪些参数

| 配置项 | `medium19` | `medium1728` |
|---|---|---|
| 数据目录 | `data/examples/wheeled-medium-sample19` | `data/examples/wheeled-medium-peak` |
| 地图 | `data/layouts/expansion-candidates/medium/layout.json` | 相同 |
| 地图规模 | 120×90米、48货架、2304货位 | 相同 |
| 机器人配置 | `config/wheeled-medium-100.json` | 相同 |
| 机器人数量 | 100 | 100 |
| 机器人行驶速度（配置中的 `speed`） | 1.5米/秒 | 1.5米/秒 |
| 机器人组成 | A1=15、R2=15、X3=70 | 相同 |
| 扰动文件 | `config/live-sample-disturbances.json` | 注册表未配置扰动文件 |
| 扰动内容 | 第250秒起选择符合条件的搬运中机器人，将电量设为24%；选择超时600秒 | 无上述样例扰动 |
| 任务数和释放期 | 19条，1800秒 | 1728条，3600秒 |

这里的 1800 / 3600 秒表示任务输入的释放期，不能理解为到点一定结束：运行仍可能需要处理未完成任务。

#### 三、`s4173` 的两个位置参数

```bash
s4173 <运行编号> [main|ray|process]
```

例如：

```bash
s4173 warehouse-sample19-002 process
```

对应关系为：

| 输入 / 配置 | 当前值或含义 |
|---|---|
| 第一个参数 | `KG_RUN_ID=warehouse-sample19-002`，标识一次新运行 |
| 第二个参数 | `KG_WRITE_MODE=process`，选择独立进程写图；可选 `main` / `ray` / `process`，省略时为 `ray` |
| 任务集 | 函数内部固定 `--dataset-id medium19` |
| 执行后端 | `--backend ray --ray-address local --ray-num-cpus 5` |
| 页面 | `--host 127.0.0.1 --port 4173` |
| Neo4j 地址 | `bolt://127.0.0.1:47687` |
| Neo4j 数据库名 | 函数当前为 `NEO4J_DATABASE=neo4j`，以实际定义为准 |
| 状态来源 | `KG_STATE_SOURCE=neo4j` |
| 状态记录 | `KG_RECORD_AGENT_STATE=1` |

`s4173 warehouse-peak-002 process medium1728` 当前会因参数过多而报错。把运行编号取名为 `medium1728` 也不会切换任务集。

#### 四、选择当前 1728 高峰集的完整命令

下面命令与当前函数采用相同连接和运行设置，只显式选择 `medium1728`，并使用独立的新运行编号。命令仅供使用，本文整理过程中未执行；应在4173端口空闲时启动。

```bash
cd /data/zc/datasets/human_robot/warehouse-dashboard

KG_BACKEND=neo4j \
KG_RUN_ID=warehouse-medium1728-001 \
KG_WRITE_MODE=process \
KG_STATE_SOURCE=neo4j \
KG_RECORD_AGENT_STATE=1 \
NEO4J_URI=bolt://127.0.0.1:47687 \
NEO4J_USER=neo4j \
NEO4J_DATABASE=neo4j \
./run_in_lade.sh python ops/start_neo4j_live.py \
  --host 127.0.0.1 \
  --port 4173 \
  --backend ray \
  --ray-address local \
  --ray-num-cpus 5 \
  --dataset-id medium1728
```

若环境中没有配置密码，启动器会交互提示输入，输入不会回显。已有环境中的 `NEO4J_PASSWORD` / 兼容密码变量会被使用。

要改用19任务，只将最后一行改为 `--dataset-id medium19`，并使用新的 `KG_RUN_ID`。数据库名填写该 Neo4j 实例中实际存在的数据库；容器名 `warehouse-neo4j` 不用于此字段。

#### 五、历史回归输入配套的参数

历史批处理入口包括 `./run_in_lade.sh python -m backend.warehouse run`，以及项目的 `ops/warehouse_v5_release.py run --`。选择这些输入时，原地图均为：

```text
--scene data/layouts/warehouse100-wide-v2.json
--mobility legacy
```

五套 `regression` 数据应按同一目录配套加载三个参数。例如全天任务为：

```text
--dataset data/examples/regression/day
--config-json data/examples/regression/day/config.json
--disturbances-json data/examples/regression/day/disturbances.json
```

另外四套将上述三个路径中的 `day` 同时替换为 `peak`、`peak-2h`、`hotspot-2h` 或 `continuous-2d`。

| 回归任务集 | 配置机器人数量 / 行驶速度 | `charging_policy` | 原扰动文件 |
|---|---|---|---|
| `peak` | 100 / 0.8米每秒 | `critical-only` | 空列表 |
| `day` | 100 / 0.8米每秒 | `staggered` | 900秒停止90秒并请求接力；15000秒延迟30秒；30000秒电量设24%；65000秒停止120秒 |
| `peak-2h` | 100 / 0.8米每秒 | `staggered` | 空列表 |
| `hotspot-2h` | 100 / 0.8米每秒 | `staggered` | 空列表 |
| `continuous-2d` | 100 / 0.8米每秒 | `staggered` | 空列表 |

这些是输入选择与复现参数片段，不是当前无 journal 服务的完整启动命令。历史批处理 runner 仍创建本地 `journal.sqlite`，即使选择 `--knowledge-backend neo4j` 也如此；因此不能将其当作当前“只写 Neo4j”启动器的替代命令。要把这几套任务统一到当前 `s4173`，需要核对地图和端口语义的兼容性、注册数据，并扩展启动器支持范围。

`warehouse-v5` 的旧实时别名还加载 `config/live-sample-disturbances.json`；`peak1728` 的旧实时别名仅覆盖 `charging_policy=critical-only`，不会自动加载 `regression/peak/config.json` 的全部配置。完整历史配置复现应显式传 `--config-json`。

#### 六、如果“参数”指任务生成参数

下面是固定输入 `manifest.json` 中的生成元数据，运行现有 CSV 时不用再次传入。`active_slots` 是生成阶段声明的活动货位数，不一定等于实际出现任务的货位数；medium 迁移包还保留了源输入元数据，最终覆盖应以实际 CSV 为准。

| 任务集 | `scenario` | `duration_seconds` | `active_slots` | `slot_turnover_seconds` | `seed` |
|---|---|---:|---:|---:|---:|
| `wheeled-medium-sample19` | `uniform` | 1800 | 32 | 3600 | 20261027 |
| `wheeled-medium-peak` | `peak` | 3600 | 1728 | 3600 | 20261027 |
| `warehouse-v5` | `uniform` | 1800 | 32 | 3600 | 20261027 |
| `regression/peak` | `peak` | 3600 | 1728 | 3600 | 20261027 |
| `regression/day` | `uniform` | 86400 | 1728 | 21600 | 20261027 |
| `regression/peak-2h` | `peak` | 7200 | 768 | 7200 | 20261029 |
| `regression/hotspot-2h` | `hotspot` | 7200 | 576 | 7200 | 20261028 |
| `regression/continuous-2d` | `continuous` | 172800 | 128 | 21600 | 20261030 |
| `seven-patterns-20261028` | `continuous-multiday-seven-pattern-cycle` | 604800 | 1728 | 不适用单一周转间隔 | 20261028 |

热点两小时输入的 `hotspot_multiplier=4`，其余单场景包为1。单场景生成器 `backend.wide.scenarios` 使用 `--scenario`、`--duration-seconds`、`--active-slots`、`--slot-interval-seconds`、`--seed`；其中 CLI 的 `--slot-interval-seconds` 对应 manifest 的 `slot_turnover_seconds`。这些值用于说明来源，不承诺只凭参数重生成就与历史迁移后的文件逐字节相同。

七天生成器 `backend.wide.multiday` 使用 `--days 7 --tasks-per-day 6912 --seed 20261028`，并以 `--profiles` 指定逐日模式。当前七天依次为 `uniform,fixed_peak,local_hotspot,batch_pulses,moving_hotspot,tidal,mixed_recovery`，最后一天按1.25倍日量产生8640条任务。它们是同一个数据包的逐日模式，不是七个 `--dataset-id`。

`--speed` 在当前 Neo4j 启动器中表示仿真相对墙钟的倍速；配置 JSON 中的 `speed` 表示机器人每秒行驶的米数，两者含义不同。

### 后续建议

- 使用当前已支持的19任务或1728任务时，选择对应的 `--dataset-id`；各次运行使用独立编号。
- 若需要通过 `s4173` 直接切换任务集，可后续增加第三个数据集参数；当前函数仍保持原来的两个参数。
- 若需要统一运行全部九套任务，应另行处理历史地图兼容、旧数据注册以及启动器的无 journal 适配；本次整理无需额外确认。
