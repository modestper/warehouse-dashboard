### 关键结论

- 仿真后端是 Python，统一命令入口为 `python -m backend.warehouse`，实时模式为 `live`。
- `ops/start_runtime.sh` 默认启动 4173 实时页面，并顺带启动 14185 回放服务；`ops/start_medium.sh` 单独启动 14583 页面。
- 默认 medium 场景为 120×90 米、48 架、2304 货位，注册配置为 `config/live-wheeled-datasets.json`，默认数据集 ID 为 `medium1728`（1728 指任务数）。
- 当前项目 `.venv` 和相邻 `warehouse-deploy/.venv` 均不存在，上述快捷启动脚本默认会因缺少 `.venv` 而退出。
- `./run_in_lade.sh` 不指定 `LADE_ENV_DIR` 时可以回退到现有 Conda lade 环境；已确认 Python 3.13.13 及 numpy、fastapi、uvicorn、neo4j、ray 模块可发现，CLI help 可执行。
- 不要把 Conda lade 目录直接设为 `LADE_ENV_DIR`：包装脚本会尝试加载不存在的 `bin/activate`。本次试验已确认该问题，默认回退方式可用。
- 普通轮式页面使用 journal 即可；Ray 模式需先启动 Ray head，机器人图谱写入还需 Neo4j。最新手册将 `--robot-agents` 标记为弃用。

### 后续建议

当前环境可在项目根目录以前台方式启动普通轮式仿真：

```bash
./run_in_lade.sh python -m backend.warehouse live \
  --registry config/live-wheeled-datasets.json \
  --dataset-id medium1728 \
  --output-root data/local-runs \
  --mode rules --knowledge-backend journal --mobility wheeled \
  --autostart --initial-speed 60 --port 4173
```

启动后访问 `http://127.0.0.1:4173/`。本次只验证了入口与依赖发现，没有验证完整仿真启动。若要使用快捷脚本或完整 Ray/Neo4j 组合，先准备脚本需要的虚拟环境，再按启动手册执行。
