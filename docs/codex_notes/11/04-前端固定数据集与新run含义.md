# 前端固定数据集与新 run 的含义

### 任务背景

用户希望理解前端“固定数据集”下拉框和“保留记录，另开新run”按钮的含义。本文核对当前页面控件、控制请求与服务端运行切换逻辑，没有点击控件或改变运行实例。

### 关键结论

- “固定数据集”是预先准备好的实验输入，主要包括 `tasks.csv`、`initial_inventory.csv`、`manifest.json`，注册项还关联布局、机器人/调度配置及可选扰动。
- 下拉框用于选择**下一次新运行使用的输入**；只改变选项不会立即替换当前运行的任务或进度。
- `run` 是一次独立运行实例，具有唯一 `runId`。同一数据集可以运行多次，各次运行使用独立身份记录执行过程。
- “保留记录，另开新run”会按所选输入重新初始化机器人、库存、任务状态与仿真时间，创建新的运行身份，页面转为显示新运行。
- 旧 run 的已有记录与已写入图谱数据不会因为此按钮被删除；新运行不继承旧 run 当前的库存、电量或任务进度。旧运行资源会被关闭，不会继续在后台并行执行。
- 应先暂停，再选择输入并新建 run。新 run 是否自动开始取决于服务启动时的 `autostart` 设置：启用时自动运行，否则处于 ready 状态等待开始。
- “继续/开始”用于推进当前 run；“保存检查点”用于保存当前状态；“另开新run”用于从数据集初始条件重新开始一次实验。

#### 按钮与数据的对应关系

| 页面内容或操作 | 实际含义 |
|---|---|
| 固定数据集下拉框 | 选下一次运行要加载哪份任务、初始库存及配套场景 |
| `medium19` | medium 布局的 19 任务示例，带低电接力扰动 |
| `medium1728` | medium 布局的 1728 高峰任务输入 |
| 暂停后再点开始/继续 | 沿用同一 runId，从原进度继续 |
| 保存检查点 | 保存当前 run 的状态，不创建新 run |
| 保留记录，另开新run | 保留旧运行记录，按下拉框输入创建新的独立运行 |

具体下拉框有哪些选项由服务启动时使用的注册表决定。`config/live-wheeled-datasets.json` 有两个 medium 选项；当前 `config/live-datasets.json` 另注册了历史布局的全天、多日等输入。不同选项可以对应不同地图和物理模型，不能把所有数据集都理解为当前 medium 地图的任务数量变化。

例如当前使用 `medium19`，已经完成 8 个任务：

```text
继续当前运行：保留同一 runId，沿用当前库存、机器人状态和 8 单完成进度。
另开 medium19：获得新 runId，从原始库存和第 0 秒重新执行这 19 个任务。
另开 medium1728：获得新 runId，加载 1728 单对应的初始输入，重新开始。
```

“保留记录”不表示界面会同时运行两个场景，也不表示选择下拉框就能返回旧进度；恢复旧运行属于单独的恢复入口。保留的内容以当前启用的持久化和图谱配置实际已写入的数据为准。

#### 当前实现位置

- `dist/index.html` 第 141 行附近：`datasetSelect` 的无障碍标签明确写为“下一次运行的数据集”，并提示“先暂停再切换输入。旧run与图谱保留”。
- `dist/original-knowledge.mjs`：下拉变更只保存待选项；按钮在运行中拒绝操作，确认后调用 `control('reset')`。
- `dist/original-platform.mjs:platformControl()`：将页面 `reset` 映射为服务端 `new_run`，携带下拉框的 `dataset_id` 和当前 `expected_run_id`。
- `ops/warehouse_live.py` 的 `/api/control`：只接受已注册且输入可用的数据集别名。
- `ops/warehouse_live_runtime.py:_control()`：运行中禁止创建新 run；暂停、就绪或完成后可创建新实例。
- `ops/warehouse_live_runtime.py:_create_run_impl()`：生成新运行身份，加载输入与配置，创建新仿真器和独立输出目录，保存初始边界。
- `ops/warehouse_live_runtime.py:_create_run()`：新运行初始化成功后才关闭旧资源；若初始化被拒绝，则恢复旧运行引用并保留旧现场。
